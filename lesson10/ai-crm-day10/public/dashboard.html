Day 10 — Graceful Error Handling (400 Errors)

Express validation & standardized 400 responses for API robustness and developer experience.

About this project

This CRM demonstrates graceful error handling for invalid input. The API uses validation middleware (e.g. Joi) so bad data never reaches business logic. When a client sends invalid payloads (missing email, malformed phone, invalid source), the server returns a 400 Bad Request with a consistent JSON structure: status, errorCode, message, and details[].

That contract improves robustness, keeps data intact, and gives API consumers clear feedback to fix requests. Use the actions below to add leads (valid → metrics update in real time) or trigger validation errors and see the 400 response.
